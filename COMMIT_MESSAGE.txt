Migrate from Angular to PyGame frontend and add RL infrastructure

This commit represents a major refactoring of the Push Fight application,
replacing the Angular web frontend with a PyGame-based desktop application
and adding comprehensive reinforcement learning support.

## Frontend Migration

### Removed
- Entire `frontend/` directory (Angular application)
- Angular dependencies and build configuration
- Web UI components and services
- Angular-specific routes in Flask app

### Added
- **PyGame UI** (`app/pygame_ui/`):
  - `main.py`: Main application loop and window management
  - `game_view.py`: Game state management and view logic
  - `board_renderer.py`: Board visualization with piece rendering
  - `input_handler.py`: Mouse and keyboard input handling
  - `ui_components.py`: Reusable UI components (buttons, panels)
  - Features:
    - Visual board with colored pieces (white/brown, square/round)
    - Anchor position highlighting
    - Valid move highlighting
    - Direction buttons (↑ ↓ ← →) for push actions
    - Skip moves button for faster gameplay
    - Save/load game functionality
    - Status panel showing current player and game phase

## CLI Improvements

### New Module
- **Enhanced CLI** (`app/cli.py`):
  - Color-coded terminal output with ANSI codes
  - Optimized board rendering (cached color support, list-based string building)
  - Combined coordinate input (`y,x` or `y x` format)
  - Quick commands (q=quit, s=save, l=load, n=new, h=help)
  - Skip moves functionality (Enter to skip, default behavior)
  - Save/load game support
  - Improved error messages and user feedback

### Main Entry Point Updates
- `app/main.py`:
  - Removed CLI functionality (moved to `app/cli.py`)
  - Supports `--pygame` (default) and `--web` modes
  - CLI now accessible via `python -m app.cli`

## Reinforcement Learning Infrastructure

### New RL Module (`app/rl/`)
- **Gymnasium Environment** (`env.py`):
  - Full Gymnasium API implementation
  - Observation space: 10x4x5 array (board state with features)
  - Action space: 1760 discrete actions (moves + pushes)
  - Reward function: +1.0 win, -1.0 loss, -0.1 invalid action
  - Automatic phase detection (move vs push)
  - Valid action filtering

- **Agent Interfaces**:
  - `agent_interface.py`: Simple agent interface (no Gym dependency)
  - `base_agent.py`: Base agent class with utility methods
    - `get_valid_moves()`: Get all valid moves for current player
    - `get_valid_pushes()`: Get all valid pushes for current player
    - `evaluate_position()`: Simple position evaluation heuristic
  - `random_agent.py`: Example random agent implementation

- **Documentation**:
  - `RL_TRAINING.md`: Comprehensive guide for training RL agents
  - Examples for Stable-Baselines3 and custom agents
  - Usage patterns and best practices

## Game Rule Updates

### Winning Conditions
- **Updated victory logic** (`game_state.py`):
  - Round piece pushed off → owner loses immediately
  - Two square pieces pushed off → owner loses (changed from "all squares")
  - Added `count_square_pieces()` method for tracking
  - Added `check_game_over()` method for state evaluation
  - Updated `check_for_victory()` to handle new rules

### Push Rules
- **Anchor behavior**:
  - Pushes against anchored pieces are now allowed
  - Pieces blocked by anchor don't move, but push is still valid
  - Anchor position still updates after push
  - Prevents pieces from disappearing when pushing against anchor

- **Kill zone blocking**:
  - Pushes into kill zones are now blocked
  - Validation occurs before push execution
  - Side rails still block pushes (unchanged)
